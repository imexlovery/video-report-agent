# Core 候选方向与待办

## 待解决问题

- **组件复用与自检收敛的发布**：主报告已限制为复用现有 UI 组件，Skill 和 Pi 任务提示明确集中检查、至多一次修订；保留来源冲突处理和防御性措辞禁令。本地固定转写验证已观察到禁绘、请求数与长尾改善，当前未推送或部署。素材内矛盾的表达仍有残余问题，不能用效率指标代替保真结论；原始输出、同价费用对比与具体缺陷见忽略的 `.local/evals/benchmark-v1/components-only-deepseek-1017-20261027/comparison.md`。
- **Brief 表格视觉验证**：短标签与长说明方案已采纳，但候选桌面、窄屏与交互验证因先前浏览器限制未完成。继续时沿用原模板和实际内容，见 [设计偏好](report-design-preferences.md#brief短标签与长说明表格)。

## 候选方向（未整体采纳、未排期）

- **既有实验与分支暂缓**：术语修正、Promptfoo 评测及 Knowledge Desktop 保留各自分支和本地材料，暂不合并或继续扩展。当前先采用精简 Skill 并用固定转写检查最新 DeepSeek 1017 的质量、请求数、耗时与费用；后续优化由本轮实际问题决定。
- **完整 CLI 的 Python 安装包**：保留下载、转写、报告生成和渲染流水线及必需资源，排除开发文档、测试和评测材料；继续从同一 Core 源码构建。当前保留完整源码安装说明，是否提供独立安装包按实际用户需求决定。
- **自绘图示开关与独立绘图会话（延后）**：当前主报告禁止自由绘图。用户已选择后续在生成前提供开关、同一轮完成正文和图示，并提出由主 Agent 判断必要性、位置与解释目标，再把相关原文、来源 ID 和样式约束交给独立上下文的绘图子任务。候选通过专用 Pi 工具启动新进程／会话，仅返回图示、图注与来源映射，由程序按预留位置嵌入 HTML；绘图过程与完整报告历史不回灌主上下文，绘图子任务不负责改写正文。Pi 提供[隔离上下文的子 Agent 扩展示例](https://github.com/earendil-works/pi/tree/main/packages/coding-agent/examples/extensions/subagent)，当前报告入口尚未接入。绘图仍需单独限定轮数、时间与费用，保留集中自检约定；独立会话本身不保证更快、更便宜或更准确。尚未批准实施；正式实现时需明确调整现有单链约定中仅涉及绘图的边界，并核对部署使用的 Pi 版本。既有图形设计经验见 [设计偏好](report-design-preferences.md#standard图示可靠性与复杂度取舍)。
- **独立报告内的证据回查**：将已有来源绑定用于可操作的原文、时间戳与视频定位，让下载后的 HTML 也便于核对关键结论；与 Knowledge Desktop 的阅读入口衔接，避免重复建设检索系统。
- **稀疏画面辅助理解（延后）**：用户明确先收尾现有分支，本方案保留，当前不推进实验或实现。以有限帧数补充转写，原始帧与文字共享时间轴，首轮保持报告版式；后续重启时再确定模型和调用预算。抽帧、来源关系、Core 接入点与分阶段实验见[合并方案](sparse-visual-understanding.md)，会员权益和收费仍为调用方候选。
- **按阅读目标组织报告**：允许用户说明关注的问题、已有背景和用途，在保留 Standard/Brief 模式及来源边界的前提下调整内容重点。先验证同源报告是否更能帮助用户完成指定任务。
- **报告局部修订**：支持对指定段落或章节提出修订要求，复用已有转写，保留原报告与可查看的差异；先验证局部改动能否保留相邻内容和来源关系。
- **CLI 直接导入已有材料**：独立 Skill 已支持转写与字幕，候选是在标准 CLI 中补齐直接导入入口，再按需求考虑本地音视频，减少对单一视频平台下载入口的依赖。
- **可继续编辑的报告导出**：探索保留标题层级、表格与来源链接的 Markdown 导出，方便用户继续整理和使用；先确认真实使用需求，再考虑其他格式或外部应用集成。

没有新增已确认功能排期。候选保留不代表实施授权；产品级方向与跨仓发布由 Service 统筹，Core 不另维护一份完整产品路线图。
